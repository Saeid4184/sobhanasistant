# سرویس‌های سرور — دستیار سبحان بتن

دو سرویس اینجاست. هر دو روی **Node.js** کار می‌کنند، کتابخانه‌ی بیرونی لازم
ندارند و فقط می‌خوانند و می‌نویسند روی دیسک خودِ سرور.

| سرویس | فایل | پورت | کارش |
| --- | --- | --- | --- |
| `sobhan-sync` | `sync-server.js` | ۸۷۸۸ | گوشی و ویندوز را رکورد به رکورد یکی می‌کند |
| `sobhan-bale` | `bale-bridge.js` | ۸۷۹۰ | عکس مستندات مقاطع پمپ را از گروه بله می‌گیرد |

`sobhan-ai` (پورت ۸۷۸۷) و `sobhan-gps` از قبل نصب‌اند و این بسته کاری با آن‌ها ندارد.

---

## کدام سرور؟

- **`sobhan-bale` باید روی سرور ایران باشد** (همان جایی که `sobhan-gps` است).
  `tapi.bale.ai` از سرور خارج در دسترس نیست. این یک محدودیت واقعی است، نه سلیقه.
- **`sobhan-sync` هم بهتر است روی سرور ایران باشد:** گوشی مستقیم به آن می‌رسد و
  داده‌ی کارگاه از کشور بیرون نمی‌رود. اگر روی سرور خارج گذاشتی، پورت ۸۷۸۸ را
  باید از پل ایرانی فوروارد کنی.

---

## نصب — سه فرمان

فایل‌ها را روی سرور بگذار (مثلاً در `~/sobhan-server`)، بعد:

```bash
cd ~/sobhan-server
chmod +x install.sh
sudo ./install.sh
```

اسکریپت این کارها را می‌کند:

1. وجود `node` را بررسی می‌کند.
2. فایل‌های js را در `/opt/sobhan/` می‌گذارد.
3. اگر `sync.env` و `bale.env` نبودند، از نمونه می‌سازد با دسترسی `600`.
   **اگر بودند، دست نمی‌زند** — پس چند بار اجرا کردنش بی‌خطر است.
4. یونیت‌های systemd را نصب و فعال می‌کند.
5. اگر `APP_TOKEN` پر بود سرویس را بالا می‌آورد و `health` را صدا می‌زند؛
   اگر خالی بود سرویس را راه نمی‌اندازد و به تو می‌گوید کدام فایل را پر کنی.

فقط یکی را می‌خواهی؟ `sudo ./install.sh sync` یا `sudo ./install.sh bale`

### بعد از نصب: رمزها

```bash
openssl rand -hex 24          # یک رمز بساز
sudo nano /opt/sobhan/sync.env   # APP_TOKEN را بگذار
sudo nano /opt/sobhan/bale.env   # BALE_TOKEN و APP_TOKEN را بگذار
sudo systemctl restart sobhan-sync sobhan-bale
```

`APP_TOKEN` می‌تواند در هر دو فایل یکی باشد — همان رمزی که در اپ وارد می‌کنی.

### پورت‌ها

```bash
sudo ufw allow 8788/tcp
sudo ufw allow 8790/tcp
```

---

## بررسی سلامت

```bash
curl -s localhost:8788/sync/health | python3 -m json.tool
curl -s localhost:8790/bale/health | python3 -m json.tool
```

`sync/health` باید بدهد: `{"ok":true,"token":true,...}`

- `token:false` یعنی `APP_TOKEN` در `sync.env` خالی است و سرویس هیچ داده‌ای
  نمی‌دهد (این عمدی است: نشانی باز = دسترسی آزاد به داده‌ی کارگاه).
- `bale/health` با `token:false` یعنی `BALE_TOKEN` نیامده است.

لاگ:

```bash
sudo journalctl -u sobhan-sync -n 50 --no-pager
sudo journalctl -u sobhan-bale -f
```

## وصل کردن اپ

**همگام‌سازی:** اپ ← تنظیمات ← کارت «همگام‌سازی گوشی و ویندوز»
- آدرس: `http://آی‌پی‌سرور:8788`
- رمز: همان `APP_TOKEN`
- «همگام‌سازی خودکار» را تیک بزن، بعد «همگام‌سازی الان»

**بار اول:** اول روی دستگاهی که داده دارد (گوشی) یک بار همگام‌سازی کن، بعد روی
ویندوز. از آن به بعد خودکار است و ترتیبش مهم نیست.

**پل بله:** اپ ← گزارش و نمودار ← زیربخش پمپ ← «تنظیم پل بله»
- آدرس: `http://آی‌پی‌سرور:8790` و همان `APP_TOKEN`
- بعد «دریافت اسناد از گروه بله»

پیش از آن: ربات بله را بساز، به گروه رانندگان پمپ اضافه کن و **ادمینش کن**.
جزئیات در `../docs/README-BALE.md`.

## محدودسازی هر کاربر (وقتی هر نفر گوشی خودش را دارد)

بدون این بخش، هر دستگاهی که `APP_TOKEN` را داشته باشد **همه‌ی داده‌ی کارگاه** را
می‌گیرد. پنهان‌کردن در اپ جلوی چشم را می‌گیرد، نه جلوی دسترسی را. مرز واقعی
اینجاست.

۱. در اپ: تب **کاربران** ← **«فایل دسترسی سرور»** ← **«گرفتن فایل»**.
   اپ برای هر کاربر یک توکن اختصاصی می‌سازد و فایل `sync-users.json` می‌دهد.

۲. فایل را روی سرور بگذار و سرویس را دوباره راه بیانداز:

```bash
sudo cp sync-users.json /opt/sobhan/sync-users.json
sudo chmod 600 /opt/sobhan/sync-users.json
sudo systemctl restart sobhan-sync
curl -s localhost:8788/sync/health        # باید scoped:true بدهد
```

تغییر بعدیِ همین فایل را سرویس خودش می‌خواند و نیازی به راه‌اندازی مجدد نیست.

۳. روی گوشی هر نفر، **یک بار**: تنظیمات ← همگام‌سازی ← آدرس سرور و **توکن خودِ او**
   (از همان جدولی که اپ نشان داد). بعد از اولین همگام‌سازی، حساب کاربری‌اش روی
   گوشی می‌نشیند و از آن پس با رمز خودش وارد می‌شود.

### چه کسی چه چیزی می‌گیرد

| نقش | داده‌ای که به گوشی‌اش می‌رسد | نوشتن |
| --- | --- | --- |
| ادمین | همه‌چیز | بله |
| مدیر کارخانه | همه‌چیز | **نه** — پوشش بی‌اثر است |
| سرشوفر | فقط کمپرسی و تریلی: دستگاه‌ها، توقف، سرویس، خرابی، و فهرست پرسنل | **نه** |
| راننده | فقط دستگاه خودش، برگه‌های خودش، و حساب کاربری خودش | بله، فقط مال خودش |
| اوپراتور بچینگ | فقط برگه‌های خودش و پرسنل خودش | بله، فقط مال خودش |

سرویس هم در **گرفتن** و هم در **پذیرفتن** این مرز را نگه می‌دارد: اگر گوشی راننده
رکوردی به نام شخص دیگر یا برای دستگاه دیگری بفرستد، رد می‌شود و در لاگ
«رد شد» ثبت می‌شود. حذفِ رکوردی که مال او نیست هم پذیرفته نمی‌شود.
`/sync/export` و `/sync/stats` فقط با دسترسی کامل باز می‌شوند.

### آنچه این لایه حل نمی‌کند

داده‌ای که روی گوشی هر نفر نشسته است **رمزنگاری نشده**. کسی که گوشیِ باز را در
دست داشته باشد می‌تواند همان مقدار داده‌ی مجاز خودش را خام ببیند. ورود با رمز
جلوی اشتباه و دست‌درازی معمولی را می‌گیرد، نه کسی را که عمداً دنبالش باشد.

## همگام‌سازی چطور کار می‌کند

- **ادغام است، نه جایگزینی.** اگر روی گوشی ساعت‌کارکرد یک میکسر را عوض کنی و
  هم‌زمان روی ویندوز یک ماشین جدید اضافه کنی، هر دو می‌مانند.
- اگر **همان رکورد** روی دو دستگاه عوض شود، تغییر جدیدتر می‌ماند.
- **حذف هم منتقل می‌شود** و رکورد حذف‌شده روی دستگاه دیگر زنده نمی‌شود.
- داده در `/opt/sobhan/sync-data.json` است، با یک کپی روزانه‌ی `.bak` کنارش.
  نوشتن اتمیک است؛ اگر برق برود فایل نیمه‌کاره نمی‌ماند.
- پشتیبان کامل از سرور:
  ```bash
  curl -s -H "x-app-token: رمزت" localhost:8788/sync/export > backup.json
  ```

### محدودیت‌هایی که باید بدانی

- **عکس‌ها همگام نمی‌شوند** (عکس خرابی‌ها در IndexedDB گوشی می‌ماند). بقیه‌ی
  داده‌ها بله.
- سنگ‌قبرِ حذف‌ها ۱۸۰ روز نگه داشته می‌شود. دستگاهی که بیشتر از ۱۸۰ روز همگام
  نشود، ممکن است رکوردهای حذف‌شده را دوباره بفرستد.
- بدون HTTPS رمز روی شبکه ساده می‌رود. اگر دامنه داری، Caddy دو خط است:
  ```
  sync.yourdomain.com {
      reverse_proxy 127.0.0.1:8788
  }
  ```

## نشانی‌ها

### همگام‌سازی (هدر `x-app-token` لازم است، جز health)

| نشانی | کار |
| --- | --- |
| `GET /sync/health` | وضعیت سرویس، بدون رمز |
| `POST /sync` | ادغام و دریافت تغییرات (کار خود اپ) |
| `GET /sync/stats` | تعداد رکورد هر مجموعه و دستگاه‌های دیده‌شده (فقط دسترسی کامل) |
| `GET /sync/export` | خروجی کامل داده برای پشتیبان (فقط دسترسی کامل) |

### پل بله

| نشانی | کار |
| --- | --- |
| `GET /bale/health` | وضعیت سرویس، بدون رمز |
| `GET /bale/docs?since=&limit=` | فهرست اسناد تازه |
| `GET /bale/file/<uid>` | خود تصویر |

پل بله هیچ چیزی به گروه نمی‌فرستد؛ فقط می‌خواند.

## متغیرهای تنظیم

**`sync.env`**

| متغیر | پیش‌فرض | کار |
| --- | --- | --- |
| `APP_TOKEN` | — | **اجباری.** رمز اپ |
| `PORT` | ۸۷۸۸ | پورت |
| `DIR` | `/opt/sobhan` | پوشه‌ی داده |
| `TOMB_DAYS` | ۱۸۰ | چند روز سابقه‌ی حذف نگه داشته شود |
| `USERS_FILE` | `/opt/sobhan/sync-users.json` | فایل دسترسی کاربران |
| `MAX_BODY_MB` | ۳۲ | سقف حجم هر درخواست |

**`bale.env`**

| متغیر | پیش‌فرض | کار |
| --- | --- | --- |
| `BALE_TOKEN` | — | **اجباری.** توکن ربات بله |
| `APP_TOKEN` | — | رمز اپ |
| `PORT` | ۸۷۹۰ | پورت |
| `DIR` | `/opt/sobhan/bale` | پوشه‌ی عکس‌ها |
| `POLL_SEC` | ۶۰ | هر چند ثانیه گروه را بخواند |
| `CHAT_ID` | همه | اگر پر باشد فقط همان گروه |

```bash
sudo ./install.sh
```
